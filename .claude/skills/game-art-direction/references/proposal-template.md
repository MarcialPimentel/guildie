# Proposal page template

Use these sections in this order, both on the published page (after the mock-up) and in `docs/art-direction.md`. Keep each section short; tables do most of the work.

## 0. Hero + mock-up

- Eyebrow: "<Game> · art direction proposal · draft for <owner>".
- Title: the new world's name ("Welcome to Portovela").
- One-sentence lead: from what, to what.
- The playable stage, then one line of controls help and "numbers are fake; the server decides".

## 1. The short version

Five cards, one per change: setting, palette, interaction, technology, how art gets made. One or two sentences each.

## 2. Setting

- Two option cards: **A. Recommended** and **B. Low-change**. For each: era and place, how the progression story maps, why it fits, what it costs.
- Ask yourself: which real place, era or culture makes this game's mechanics feel native? What does the late-game "power fantasy" become in this setting (steam → water wheels and clockwork)?
- Rename table: Today | New | Why. Display names only; call out permanent IDs that stay.
- One tone rule (e.g. "seasoning, not a costume"; no caricature).

## 3. Palette

- Short intro naming the mood and what's being retired, with the old swatches shown small.
- Day swatches and night swatches. Each: name, hex, role, and for text colors the contrast ratio.
- A line on world-only colors (building pastels, foliage, water) that never become UI text.
- Every swatch sets its own text color so it reads in either page theme.

## 4. Type and icons

- Specimen card: display face on a real in-game headline, body face on a real in-game sentence.
- Icon card: three to five real icons on their tile, plus the icon rules in one paragraph.
- "How a menu looks now": two or three real list rows (e.g. market rows) built from the page tokens, so they preview both themes.

## 5. Interaction map

Table: System | Where it lives | What the player does | Builds on (existing server action or system). One row per player-facing system. Lead with the rule: every system gets a place and a verb; menus open from the world; the server still decides.

## 6. Technology

- Layer diagram (HTML menus / 3D world / game state + API / server), marking what's new and what's unchanged.
- Options table with a one-line verdict each, recommendation first.
- Three budget cards: loading, geometry and textures, frame rate and battery.

## 7. Making the art

- Three cards: placeholders now, hero pieces, later (hire an artist).
- Numbered steps for the owner to make one hero model.
- A copyable concept prompt in the new style (object line first, then style, palette, framing).
- A note to check commercial-use terms of AI tools.

## 8. Conflicts with the design docs

Table: Section | Says today | Would say. Say that you'll update the docs and decision log once approved, in the same change as the first visual work.

## 9. Plan and decisions

- Numbered phases (reskin current UI → hidden 3D test slice → first system in 3D → whole world → final art).
- A highlighted "What I need from you" card with each decision as a direct question.
- One line on risks (3D costs more per feature; art is the slowest part; menus remain as a fallback).
